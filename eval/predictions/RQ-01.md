# Prediction: RQ-01

Registered: 2026-10-23, committed before the arm's first world. Frozen after the commit that registers it; an amendment is a new
dated section, and any change made after seeing results turns the arm into a hypothesis, not evidence.

Citations marked UNVERIFIED were not read or measured when this draft was written; everything else
cites a file and line, a URL, or a measurement over the recorded corpus that was made for this draft.

## Arm

| Field | Value |
|---|---|
| Target | `targets/rqlite`: upstream rqlite 10.5.3, three voting nodes, image pinned by digest (`docker-compose.yaml:44`) |
| Control type | negative control; calibration pole PASS (`expected: 0`, `gold_positive`) |
| Variant | reads at `level=linearizable`, writes to the believed leader only |
| Profile | `p2-linear` (`prothesis.yaml:93`): budget 10m, `worlds: 1`, driver profile `linear` (16 clients, 60,000 ops, half writes, half `read_linearizable`; `prothesis.yaml:60`) |
| Fault schedule | `net.partition(role:leader)@3000..7500` |
| Target oracle | none (a PASS pole) |
| N and seeds | 10 runs, one world each: `thesis run --arm RQ-01 --seed s` for s = 1, 2, ..., 10 |

Each run's exit code is the calibrated one (`pkg/schema/calibration.go:114-129`): PASS is TRUE_PASS and
exits 0, FAIL is a FALSE_REJECTION and exits 1, INCONCLUSIVE exits 2.

## Expected verdict

**PASS in 10 of 10 runs (point estimate); registered: at least 8 PASS and no FAIL.** At most 2 runs are
expected to be INCONCLUSIVE (exit 2).

There is no prior: no world of this target has run under a fault. One fault-free `smoke` world reached
ASSERT during onboarding (`README.md:11-13, 79-83`).

## Expected mechanism

1. The role probe (`cmd/rqliterole`) names the leader; the partition binds to it and lands at about
   t+3000 ms (`world.thesis` `fault_schedule.realized`).
2. A linearizable read makes the receiving leader check that it is leader; "Next the node heartbeats with
   the Followers, and waits until it receives a quorum of responses", and then waits until the write at the
   recorded commit index is applied (https://rqlite.io/docs/api/read-consistency/, read for this draft).
3. The cut-off leader cannot assemble a quorum, so its linearizable reads fail or time out, recorded as
   `fail` or `info`, never as a value (`cmd/rqliteload/main.go:25-33`). Reads go to a node chosen at random
   (`main.go:620`); reads on the connected nodes are served by the new leader once one is elected.
4. Writes go to the believed leader only, with `?redirect`; a follower answers 301 without applying, and
   the driver moves its next write to the node the redirect names (`main.go:34-40`, `README.md:64-68`).
   That writes stay on the leader under a partition is a reading of the driver's code; it has not been
   observed in a faulted world: UNVERIFIED.
5. With heartbeat and election timeouts of 1 s and a leader lease of 500 ms (`docker-compose.yaml:82-84`),
   the connected pair elects a new leader and serves linearizable reads that reflect every acknowledged
   write. `linearizable.kv` finds no violation; the built-in oracles (`no_crash`, `no_panic_log`,
   `availability_after_heal`, `no_stuck_op`; `prothesis.yaml:82`) pass when the nodes converge after the
   heal.

## Expected violation class

None. A PASS is expected because a linearizable read needs a quorum heartbeat, which the cut-off leader
cannot obtain; RQ-02 (weak) and RQ-03 (none) are the arms that relax it.

## Fault kinds expected to realize

`net.partition(role:leader)@3000..7500`, one realization per world: `fault_schedule.realized` holds one
entry whose `resolved` partition names the node the role probe reported as leader, with `start_ms` near
3000. A world with no realized entry is excluded and reported, never counted as a PASS.

## INCONCLUSIVE risks

- This target has no known-problem registry, so `thesis diagnose` runs against an empty one: any
  INCONCLUSIVE world is reported UNATTRIBUTED, not explained.
- `/nodes` reports no Raft term, so the role probe refuses when nodes disagree about the leader; the fault
  then fails to bind and the world is a harness error (INCONCLUSIVE; `README.md:99-101`). This is more
  likely here than on etcd, because a role probe that cannot rank two claims refuses every disagreement.
- `no_stuck_op` cannot judge a QUIESCE shorter than its ceiling; the checker may be unable to judge a
  history; `availability_after_heal` may time out if a node converges slowly; a version mismatch on any
  response stops the driver non-zero (`main.go:41-43`).
- **Fresh storage is not guaranteed per world (OQ-087).** Every run is launched from `targets/rqlite`
  (`eval/README.md`, Operating rules; `README.md:30-32`). Before and after each run the operator records
  this repository's compose-labelled volumes (projects named `thesis-*`) with the run id. A world whose own
  compose project had volumes before it booted is excluded and reported. Volumes of other projects are
  recorded but do not exclude a world.
- Image identity: a world counts only if `eval/tools/check-images.ps1` reads MATCH against
  `sha256:de385382ef6d93a4b4b831eac4d419cfa35fdb1515621a4ad8ba8b5a5beeb6b5` (`README.md:91-96`).

## What would falsify this

- **Verdict.** Any FAIL (a FALSE_REJECTION), or fewer than 8 PASS runs.
- **Mechanism.** A linearizable read served by the cut-off node inside the partition window that returns a
  value; or a write recorded `ok` on a node other than the one the driver believed to be leader (the
  leader-only write path did not hold).
