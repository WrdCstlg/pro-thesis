# Prediction: CO-02

Registered: DRAFT — not registered. Frozen after the commit that registers it; an amendment is a new

Citations marked UNVERIFIED were not read or measured when this draft was written; everything else

## Arm

| Field | Value |
|---|---|
| Target | `targets/consul`: upstream Consul 2.0.4 (BUSL-1.1), three voting servers, image pinned by digest (`README.md:17-26`) |
| Control type | discriminating control; calibration pole FAIL (`expected: 1`, `buggy_negative`) |
| Variant | `?stale` reads: any server answers from its own state |
| Profile | `p2-stale` (`prothesis.yaml:97`): budget 10m, `worlds: 1`, driver profile `stale` (16 clients, 60,000 ops, half writes, half `read_stale`; `prothesis.yaml:70`) |
| Fault schedule | `net.partition(role:leader)@3000..7500` |
| Target oracle | `linearizable.kv` |
| N and seeds | 10 runs, one world each: `thesis run --arm CO-02 --seed s` for s = 1, 2, ..., 10 |

Each run's exit code is the calibrated one (`pkg/schema/calibration.go:114-129`): a FAIL carrying a
`linearizable.kv` violation is TRUE_REJECT and exits 0; a PASS, or a FAIL raised only by another oracle, is
an ESCAPE and exits 1 (`calibration.go:89-103`); an INCONCLUSIVE run exits 2.

## Expected verdict

**FAIL with a `linearizable.kv` violation in 10 of 10 runs (point estimate); registered: at least 8.** At
most 2 runs are expected to be INCONCLUSIVE; none is expected to PASS.

There is no prior on this target. The closest prior is etcd's serializable-read arm, also a read any
member answers from local state: 4 of 4 recorded worlds violated `linearizable.kv` (measured for this
draft over `targets/etcd/.prothesis/runs`).

## Expected mechanism

1. The `stale` mode "allows any server to handle the read regardless of whether it is the leader"; "Results
   are generally consistent to within 50 milliseconds of the leader", "though there is no upper limit on
   this staleness" (https://developer.hashicorp.com/consul/api-docs/features/consistency, read for this
   draft).
2. Reads and writes go to a server chosen at random (`cmd/consulload/main.go:596`). A follower that has not
   yet applied a write the leader acknowledged can return the older value: replication-lag staleness that
   needs no fault, as on etcd's serializable arm, whose first stale read came 69 ms into the drive phase,
   before its partition (`targets/etcd/README.md:71-76`).
3. In addition, from about t+3000 ms the partition cuts the old leader off. It keeps answering `?stale`
   reads from its own state, which stops advancing, while the connected pair elects a leader and commits
   new writes: for the rest of the 4.5 s window, every read it answers of a key written by the majority is
   stale.
4. `linearizable.kv` raises a stale read at ASSERT and the run is FAIL.

## Expected violation class

Consistency: a stale read of a key, answered by a server whose state had not applied a write acknowledged
before the read was invoked. The witness may sit on any server (lag) or on the partitioned one (the
partition); the verdict prediction does not depend on which.

## Fault kinds expected to realize

`net.partition(role:leader)@3000..7500`, one realization per world: `fault_schedule.realized` holds one
entry whose `resolved` partition names the server the role probe reported as leader, with `start_ms` near
3000. A world with no realized entry is excluded and reported: the arm is registered with the fault.

## INCONCLUSIVE risks

- This target has no known-problem registry, so `thesis diagnose` runs against an empty one: any
  INCONCLUSIVE world is reported UNATTRIBUTED, not explained.
- The checker can return INCONCLUSIVE on a history it cannot judge: it did on 10 of the fixture's 112
  recorded buggy-build worlds under this fault (measured for this draft).
- The role probe refuses when servers disagree about the leader (`README.md:180-182`); the fault then fails
  to bind and the world is a harness error (INCONCLUSIVE).
- `availability_after_heal` may time out if a server converges slowly.
- **Fresh storage is not guaranteed per world (OQ-087).** Every run is launched from `targets/consul`
  (`eval/README.md`, Operating rules). Before and after each run the operator records this repository's
  compose-labelled volumes (projects named `thesis-*`) with the run id. A world whose own compose project
  had volumes before it booted is excluded and reported. Volumes of other projects are recorded but do not
  exclude a world.
- Image identity: a world counts only if `eval/tools/check-images.ps1` reads MATCH against
  `sha256:1c59f007df8ea1c21b2558dc73ef8d99047bc895d9e52e635d1e745e35fe9a54`.

## What would falsify this

- **Verdict.** Fewer than 8 of the 10 runs FAIL with a `linearizable.kv` violation, or any run PASSes.
- **Mechanism.** Scored on where the stale reads are: if the first stale read precedes `start_ms`,
  replication lag produced the FAIL and the partition was not needed (recorded as such); if every stale read
  is on the partitioned server inside the window, the partition produced it. A stale read on a server that
  had already applied the write it misses falsifies both.
