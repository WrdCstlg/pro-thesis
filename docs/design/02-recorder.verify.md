# 02-recorder.verify

## Verdict

**NEEDS-REVISION**

## Spec fidelity

Multiple normative alterations, several of them violations of directive rule 2 ("Normative Schemas are Frozen ... Do not invent, alter, or improvise field names or semantics").

1. VERDICT FIELD TYPE CHANGED. Spec §4.6 `prothesis.verdict/v1` shows `"confidence": 0.42`: a JSON number. Design §3.1: "For the one place the spec genuinely shows a float (`verdict.suspect.confidence: 0.42`) we use `schema.Dec`, an exact decimal serialized as a string at a per-field declared scale (`cjson:"confidence,dec=2"` → `"0.42"`)". That emits a string where the frozen schema says number. §4.4 confirms verdict.json is under the no-float CJSON contract, so this is not optional.

2. FAULT GRAMMAR CONVERTED FROM POSITIONAL TO NAMED. Spec §4.3 fixes `KIND(TARGET[, PARAMS])@WINDOW` with positional params: `net.latency(mean,jitter)`, `net.loss(pct)`, `io.error(rate)`, `proc.kill(signal)`. Design: `Params map[string]int64` plus "`String` renders the normative grammar KIND(TARGET[, k=v...])@START..END with params in sorted-key order", plus a ppm rewrite (`net.loss(pct)` → `loss_ppm`, `io.error(rate)` → `rate_ppm`). `Fault.String()` is declared to be "what appears in `verdict.shrink.surviving_faults`": a frozen field whose normative values are `"proc.pause(role:leader)@8200..15100"`. `proc.kill(SIGKILL)` is unrepresentable in `map[string]int64` at all.

3. ORACLE_INPUT PHASE SEMANTICS ALTERED. Spec §4.5 `prothesis.oracle_input/v1` shows `{"phase": "DRIVE", "start_ms": 0, ...}`, all non-negative. Design §1.1: "`BOOT` and `SEED` appear in `phases` with negative `start_ms`. We emit them anyway ... Documented deviation from the illustrative example." No built-in oracle (§6 Phase 1) and no oracle class (addendum §B) is declared valid in BOOT or SEED, so the deviation buys nothing and breaks third-party oracles that index by ms.

4. EXIT CODES REASSIGNED. Spec §4.7 and addendum §I: `3 = BUDGET_EXHAUSTED — Budget expired without coverage progress`. Design §1.6 table: "budget expires / **Ctrl-C** mid-schedule → ... **3**". A user interrupt is not budget exhaustion, and the recorder cannot know whether coverage progressed. Separately `5 = CONFIG_ERROR — Invalid prothesis.yaml or CLI arguments`, but `Compile` returns "config error, not a silent skip ... exit **5**" for a fault window inside a `.thesis` world file, which is neither a yaml nor a CLI argument. Also: the recorder assigning exit codes at all contradicts §3, which makes `internal/control` the "exit code coordinator".

5. NO EXIT CODE DEFINED FOR THE FAILURE THE DESIGN CALLS ITS TOP RISK. `ErrNonCanonical`, `ErrHashMismatch` and the CRLF case have no mapping. Under addendum §E.4 a committed regression `.thesis` that no longer loads is functionally a removal of a regression test, i.e. exit 4 ORACLE_DRIFT, not a generic load error.

6. NEW SCHEMA IDS AND CLI VERBS INVENTED. `prothesis.world/v1`, `prothesis.run/v1`, `prothesis.manifest/v1` are not in the spec. Defensible (the spec names no world schema), but they need DECISIONS.md entries and they enter `.prothesis/lock` in Phase 3, so naming them casually is a future ORACLE_DRIFT event. `thesis world canonicalize` and `thesis report --bundle` are not in addendum PART 7's CLI surface (which has `thesis report RUN_ID [--format json|md|html]`), and `thesis world canonicalize` is load-bearing: the design requires it be named in the `ErrNonCanonical` message "from day one".

7. THE DESIGN CONTRADICTS ITS OWN FROZEN RULE. §4.4 places `timeline.jsonl` under the CJSON contract; CJSON rule 2 caps numbers at 2^53−1 (9007199254740991); the §4.4 example line is `{"kind":"clock.origin","rt_ns":42101300000,"wall_ns":1788451200000000000}`: 1.788e18, ~199× over the cap.

CHECKED AND CORRECT, not faulted: the `world_hash` projection is exactly I2's tuple `(seed, topology_variant, driver_profile, fault_schedule, phase_timings)`; the PhasePlan-input / PhaseSpan-output split resolving I2's ambiguity; `HexU64` for the seed; the 2^53 ns ≈ 104.25 days claim for `rt_ns`; the Lemire bound `t := (-n) % n == 2^64 mod n` (correct, and the same idiom math/rand/v2 uses); `float64(u>>11) * (1.0/(1<<53))` exactness; `os.Rename` → `MoveFileEx(MOVEFILE_REPLACE_EXISTING)`; monotonic stripping by `Round(0)`/`MarshalJSON`; `math.Sqrt` correctly rounded while `math.Log` is not; HMAC 0x01/0x02 domain separation; the argument that key-tree derivation makes stream independence structural rather than disciplinary.

## Confirmed problems (20)

### P1 [high] `Sequencer.dispatch` calls `Actuator.Do` for withdraw events. It never calls `Undo`.

**Why it breaks:** `dispatch` is written with no branch on `ev.Op`: it logs `"fault."+ev.Op.String()+".initiated"` and then unconditionally `err := s.act.Do(dctx, ev.Action)`, then on success `s.push(ev.Action)`. The compiled event list contains an OpWithdraw event for every fault. So at `end_ms` the fault is RE-INJECTED rather than withdrawn, and a second withdrawal obligation is pushed onto the LIFO stack. For `net.partition(minority(kv))@8400..14900` the iptables rules are re-applied at 14900 and stay in force until `drain()` at end of run, which silently destroys the HEAL phase and §4.1's 'HEAL: Withdraw all injected faults; assert zero residual faults remain'. It also means the only withdrawal mechanism that actually works is the deferred drain, so no fault ever ends mid-DRIVE and Phase 2's DoD scenario (pause@8200..15100 overlapping partition@8400..14900, both ending before DRIVE ends) cannot be executed as written.

**Fix:** Branch in `dispatch`: `OpInject` -> `act.Do` then `push`; `OpWithdraw` -> `act.Undo` then `popSpecific(ev.Seq)`. Then `drain()` handles only the residue: injects whose scheduled withdraw never ran. Also state that `Undo` MUST be idempotent, since drain can still race a completed scheduled withdraw.

### P2 [high] Fire-and-forget dispatch goroutines destroy inject ordering and race `drain()`, allowing a residual fault to survive the exact cancellation path drain exists to protect.

**Why it breaks:** `dispatch` launches `go func(){ ... act.Do ... ; s.push(ev.Action) }()` with the comment 'ordering is already fixed by the loop above'. That is false: the loop fixes *initiation* order only. The design itself states docker exec latency is 100-800ms, so an inject at t=8200 and one at t=8400 (a 200ms gap) routinely take effect in reverse order. Phase 2's DoD requires proc.pause(leader)@8200 to precede net.partition(minority)@8400 for the lease bug to manifest; reversing them changes which node is leader when the partition lands. Worse, `push` happens only *after* `Do` returns. Ctrl-C between goroutine launch and `Do` returning means the deferred `drain()` runs against an empty stack, then `Do` completes and installs an iptables rule or SIGSTOPs a container that is never withdrawn: leaving the developer's Docker Desktop VM dirty. That is precisely the failure the detached-context drain was designed to prevent. Separately `s.fidelity` is written from both `Run` and every dispatch goroutine with no lock (the design says `mu` guards the withdraw stack), which is a data race, and concurrent `s.log` into a `bufio.Writer`-backed `Appender` needs locking that is never stated.

**Fix:** Register the withdrawal obligation BEFORE dispatching (`push` in the caller, mark 'pending', downgrade on Do failure). Serialize dispatch onto one worker so ordering is preserved, or at minimum serialize per-target. Make `drain()` wait on an in-flight WaitGroup before popping. Guard `fidelity` with `mu` or make it an `atomic.Int32` ordinal. Give `Appender` an internal mutex.

### P3 [high] The drift watcher computes CUMULATIVE wall-vs-monotonic divergence, not a step, so ordinary NTP slew marks long runs INCONCLUSIVE.

**Why it breaks:** `watchDrift` computes `wallDelta := time.Now().Round(0).Sub(c.wallBase)` (measured from the run's start) minus `monoDelta := time.Duration(c.NowR())`, also from run start. That is accumulated drift since t=0, not a discontinuity. The prose claims it detects 'a step: NTP step or VM resume'. A host slewing at a routine 500ppm accumulates 14.4 seconds over the 8h `soak` profile, blowing past the 2s threshold with no step ever occurring. Per §1.6 that marks the whole run `degraded` and exit 2 INCONCLUSIVE. The soak profile is exactly where this bites and exactly where a spurious INCONCLUSIVE is most expensive (8 hours of search thrown away). Docker Desktop's Hyper-V utility VM also nudges host clock behaviour under load.

**Fix:** Detect a step, not accumulation: keep the previous sample and alarm on `|(wall_i - wall_{i-1}) - (mono_i - mono_{i-1})| > threshold`. Record accumulated slew in `clock.json` as an observation only; never let it change the verdict.

### P4 [high] `timeline.jsonl`'s own example violates the design's own CJSON number rule, so the encoder as specified cannot emit it.

**Why it breaks:** §4.4 states 'Each line is an independently canonical CJSON object' and lists timeline.jsonl under the CJSON contract. CJSON rule 2 says 'Magnitude <= 2^53-1. Anything larger MUST use schema.HexU64 or a string type.' The example line is `{"kind":"clock.origin","rt_ns":42101300000,"wall_ns":1788451200000000000}`. 2^53-1 = 9007199254740991; the wall_ns value is 1.788e18, roughly 199x over. Either `Encode` rejects the record the design depends on for the wall anchor, or the rule is unenforced: in which case rule 2's stated purpose (JavaScript/MCP consumers of the verdict) is not actually guaranteed anywhere. The same collision hits any future artifact carrying Unix nanoseconds, which is every timestamp the external driver produces.

**Fix:** Represent absolute wall times as `wall_unix_ns` in HexU64 (consistent with the seed precedent), or split into `wall_unix_s` + `wall_ns_frac`, or exempt a declared allowlist of fields with an explicit `cjson:",bigint"` tag that the linter recognises. Pick one and make `Lint` enforce it.

### P5 [high] No mapping is defined from the external driver's `t_ns` to the virtual clock, which makes `oracle_input.phases` and therefore I5 unusable.

**Why it breaks:** `history.jsonl` is produced by an external `driver.cmd` and carries absolute Unix nanoseconds (§4.4 of the spec: `"t_ns":1725300000000000`). `oracle_input.phases` is expressed in virtual milliseconds. Every phase-aware oracle must decide whether op 8891 fell inside DRIVE or HEAL, which requires converting t_ns to v_ms. The design provides `Anchor()` and one `clock.origin` line carrying `wall_ns`, then explicitly writes 'Docker Desktop's Linux VM has its own clock; container log timestamps are in that clock, not ours', and stops there. On this machine the kvfixture loadgen will run either on the Windows host or inside the Linux VM, and the two clocks differ by an unmeasured offset. `NowWall()`'s comment claims it 'guarantees non-decreasing timestamps in history.jsonl, which every consistency checker requires', which is simply false: the recorder does not write history.jsonl. This is a Phase 0 decision (what anchor to record and how) that Phase 3 cannot recover from.

**Fix:** Define the conversion in Phase 0: record `driver_clock_offset_ns` measured by a handshake at DRIVE start (driver emits an `info` line with its own `t_ns` at spawn; recorder pairs it with its `NowWall()`), store it in `phases.json`/`clock.json`, and define `v_ms = (t_ns - origin_wall_ns - driver_offset_ns)/1e6`. Fix the `NowWall` doc comment. Add a Phase 0 test that a container-hosted driver's t_ns maps into the right phase.

### P6 [high] `Fault.Params map[string]int64` plus named `k=v` rendering cannot represent the normative fault grammar, and `Fault.String()` is simultaneously the world sort key and a frozen verdict field.

**Why it breaks:** Spec §4.3 fixes positional params: `net.latency(mean,jitter)`, `net.loss(pct)`, `io.error(rate)`, `proc.kill(signal)`. The design stores integers-only, ppm-rewritten, in a map, and renders `KIND(TARGET[, k=v...])@START..END`. Three consequences bite. (1) `proc.kill(SIGKILL)` is unrepresentable: signal is symbolic in the spec's own grammar line and `int64` cannot hold it, so Phase 2 either invents a signal-number encoding (drift) or the schema must change (rehashing the corpus). (2) A user-typed `net.loss(kv:*, 1.25)` re-renders as `net.loss(kv:*, loss_ppm=12500)`, so the Phase 2 grammar parser is not round-trip-faithful and `verdict.shrink.surviving_faults` (a frozen field whose normative examples are `"proc.pause(role:leader)@8200..15100"`) contains strings no one typed and the parser must then re-accept. (3) Because `String()` is also the `Event.Seq` sort key, any later fix to the rendering silently reorders same-instant faults and changes execution of every world in the regression corpus.

**Fix:** Make `Params` an ordered list of typed values (`[]Param{Name, Kind(int|string|ppm), Raw string}`) preserving the author's exact source text, or a `map[string]ParamValue` with a string arm for signals. Freeze `String()` as the normative positional grammar. Decouple the sort key from the display string: give `Fault` an explicit canonical sort tuple `(start_ms, end_ms, kind, target, params-canonical)` so a rendering change can never reorder a world.

### P7 [high] `verdict.suspect.confidence` is emitted as the JSON string `"0.42"`, altering a frozen schema field's type.

**Why it breaks:** Spec §4.6 `prothesis.verdict/v1` shows `"confidence": 0.42`, a number, and directive rule 2 freezes it. §4.4 of the design puts verdict.json under the CJSON contract, and CJSON has 'deliberately no Float', so `schema.Dec` serialises to `"0.42"`. Phase 6's DoD requires an autonomous agent to 'parse prothesis.verdict/v1'; a consumer written to the spec does `v.suspect.confidence * 100` and gets a type error. This is not cosmetic: the addendum PART 10 defensibility argument rests on the verdict being a portable, stable contract.

**Fix:** Do not apply the no-float CJSON profile to verdict.json. `.thesis` is the artifact that must be byte-identical and content-addressed; verdict.json is an output that nothing hashes. Emit it with a small float-capable canonical writer (fixed 2-decimal formatting for this one field) or plain `encoding/json` with `SetEscapeHTML(false)`. Keep the float ban where it earns its keep: inside `.thesis`.

### P8 [medium] The virtual-time origin does not exist during BOOT and SEED, so every `v_ms` the design shows for those phases is unwritable at the time it is logged, and `Timeline.V()` silently returns garbage instead of failing.

**Why it breaks:** `SetOrigin` is 'called exactly once, by the lifecycle machine, at the instant the driver process is spawned'; i.e. at DRIVE. `V(r)` is `VTime(r - RTime(t.originRT.Load()))` and does not consult the `set` flag, so before DRIVE it returns `r` itself. The §4.4 example first line is `{"kind":"phase.enter","phase":"BOOT","rt_ns":1204100,"v_ms":-42100}`. That -42100 cannot be known when BOOT is entered; what would actually be written is +1 (1204100ns). `timeline.jsonl` is append-only and flushed at every phase transition, so there is no backfill opportunity. This also bites Phase 0 DoD (a) directly: `thesis up` / `thesis down` have no DRIVE phase at all, so the origin is never set and every `v_ms` the recorder stamps during up/down is a raw monotonic reading masquerading as virtual time.

**Fix:** Make `V()` return `(VTime, bool)` or panic when `!set`; never let it produce a value silently. Omit `v_ms` from pre-origin timeline records (they already carry `rt_ns`, which is the true frame) and let a post-hoc reader derive negative v_ms from the `clock.origin` record. Have `up`/`down` use a Timeline that is explicitly origin-less.

### P9 [medium] The build-failing `time.Now`/`time.Sleep`/`time.NewTimer` ban obstructs Phase 0's harness while allowing the equivalent nondeterminism through `context.WithTimeout`.

**Why it breaks:** §1.2 says `determinism_scan_test.go` 'fails the build' if any of those appear outside `clock_real.go`/`runid.go`. But `internal/harness` (a Phase 0 deliverable) must poll health probes ('timeout: 30s'), wait for `docker compose up` readiness, and time `docker compose down`. With the ban, every such wait must route through `Clock.SleepUntilR`, which busy-spins its last 2ms per call and (per the finding above) has no valid virtual-time frame during BOOT. Meanwhile the design's own `dispatch` and `drain` use `context.WithTimeout`, which is a wall-clock timer under a different name and is not banned. So the rule blocks the code that needs writing in Phase 0 and does not block the mechanism the design itself relies on. The scanner also claims to flag 'map range whose iteration order reaches output', which is not decidable by AST inspection and will be either vacuous or noisy.

**Fix:** Scope the ban to the packages where it is actually load-bearing (perturber scheduling, driver op generation, search mutation) rather than the whole tree, and route harness polling through an explicit `Clock.Ticker`/`Clock.WithTimeout` so the seam is real rather than prohibitionary. Drop the map-range claim from the scanner's documented capability or demote it to a heuristic warning.

### P10 [medium] The two headline byte-identity tests: the fuzzer and the byte-mutation suite; are vacuous, because `DecodeWorld` internally performs the very comparison they assert.

**Why it breaks:** `DecodeWorld` fails unless `EncodeWorld(result) == b` bytewise. `FuzzWorldRoundTrip` then does `w, err := DecodeWorld(b); if err != nil { return }; out := EncodeWorld(w); if !bytes.Equal(b, out) { t.Fatal }`. The final check is unreachable unless `EncodeWorld` is nondeterministic between two consecutive calls on the same value. It cannot detect a decoder that drops a field, a decoder that mis-parses a value, or a lossy Marshal/Unmarshal pair: all of which produce `ErrNonCanonical` inside Decode and hit the `return`. The design calls this 'literally G3'; it is literally a tautology. Test 8 fails the same way: 'assert Decode either errors or yields different re-encoded bytes'; the stated purpose is to catch 'the decoder ignores this byte', but an ignored byte makes re-encoding differ from the mutated input, which is exactly `ErrNonCanonical`, which satisfies the 'errors' branch. So the test passes for the bug it was written to catch. Given Phase 0's DoD (b) IS byte-identity, the tests carrying that DoD do not test it.

**Fix:** Add a `decodeUnchecked` path (Parse -> Unmarshal, no byte-identity gate) and test the real properties against it: (i) `Encode(decodeUnchecked(b))` reproduces `b` for goldens; (ii) for byte mutations, assert the resulting World is *semantically different* from the golden World (deep-equal check), not merely that some error occurred; (iii) keep the World -> bytes -> World -> bytes idempotence test (item 3), which is the only non-vacuous one, and promote it to the DoD evidence.

### P11 [medium] `topology_variant: {name, nodes}` plus `config_hash` excluded from `world_hash` means a `.thesis` is not self-contained (I2) and the corpus dedupes worlds that are not equivalent.

**Why it breaks:** I2 requires 'Any violation must serialize to a self-contained `.thesis` file that reproduces the issue', and addendum PART 10 requires world formats 'portable across repos'. The example world's entire topology is `{"name":"kv3","nodes":3}`. Everything that actually determines the run (the compose file, node ids, service names, role_hints, health probes, the `perturber.allow` set) lives in `prothesis.yaml`, whose hash the design deliberately excludes from `world_hash` ('Fields outside it ... are PROVENANCE, not IDENTITY'). Two structurally different 3-node topologies therefore produce the same `world_hash`, collide on the content-addressed filename `w_<hash>.thesis`, and one silently overwrites the other in `.prothesis/regressions/`. Under addendum E.4 the regression corpus is append-only and its integrity is a lock concern, so a silent overwrite is an I6 hole. Conversely a regression world committed before a compose edit will replay against a different topology with no warning at all.

**Fix:** Keep `config_hash` out of the hash preimage (the dedupe argument is right) but make `DecodeWorld`/replay *verify* it and emit a loud warning or exit 4 on mismatch, and record which fields of the config it covers. Separately, expand `topology_variant` to carry the resolved node set (ids, services, role_hints) so the world is genuinely self-describing, and hash that.

### P12 [medium] Phase 0 scope violations: `determinism.Scan`, `Retain`, `Compile`, and two invented CLI verbs are all shipped in Phase 0.

**Why it breaks:** Directive rule 1: 'Under no circumstances may you skip ahead or implement phases out of order.' §5 of the design lists Phase 0 as shipping `Retain` (implements `artifacts.retain_passing`/`retain_failing`, meaningless before Phase 1 produces runs), `determinism.Scan` (whose second consumer is `thesis doctor`, addendum PART 5, not a Phase 0 command (Phase 0 CLI is init/up/down only), and `Compile`) which is the fault schedule compiler that spec §3 assigns to `internal/perturber` ('Fault grammar parser, schedule compiler, injector/withdrawer') and §6 assigns to Phase 2. `Fault.String()` implementing the normative grammar in `pkg/schema` compounds this. The design also requires `thesis world canonicalize` to exist 'from day one' and adds `thesis report --bundle`; neither is in addendum PART 7's CLI surface. The cost is not purity: it is that the recorder's advertised zero-dependency, fast, hermetic test property is what makes Phase 0 finishable on a machine where Go is not yet installed, and every one of these pulls in surface area that cannot be validated against the fixture yet.

**Fix:** Phase 0 ships: Clock (real+sim), Timeline, Streams, CJSON codec, Encode/Decode/HashWorld, Bundle, AllocRunID, SafeName. Move `Compile` and `Fault.String()` to `internal/perturber` behind the `Actuator`/event-list seam. Defer `Retain` to Phase 1 and `determinism.Scan` to Phase 6 (or wherever `doctor` lands). If `thesis world canonicalize` is genuinely required day one, add it to OPEN_QUESTIONS.md as a proposed CLI extension rather than assuming it.

### P13 [medium] Absolute host paths in `oracle_input`, combined with a project directory containing a space, break `driver.cmd` templating and Phase 3's containerised oracles.

**Why it breaks:** The working directory on this machine is `C:\AI Projects\Pro-synthesis`; it contains a space. §4.2 config templates `./bin/loadgen --history {history_path} --seed {seed}`, and §4.2 of the design says `oracle_input`'s `history_path`/`world_path` are 'absolute paths into this tree'. `SafeName` is specified for node ids only; nothing validates or quotes the artifacts root. If `driver.cmd` is split on whitespace the path is torn in two; if it is handed to a shell it must be quoted, and PowerShell/cmd/Linux-in-container quoting all differ. Separately, the Phase 3 linearizability wrapper the spec names (Elle/Knossos) is JVM/Clojure and will run in a container on this host, where `C:\AI Projects\...` is meaningless; even Porcupine-in-a-container needs a translated path. Committing Phase 0 to host-absolute paths with no translation seam makes this a rewrite later.

**Fix:** In Phase 0: define `driver.cmd` as an argv template (parse once, substitute per-token) so quoting is not the shell's problem; make `SafeName`-style validation cover the artifacts root and reject or warn on spaces; and introduce a `PathMapper` seam on `Bundle` (`Host(rel)` / `Oracle(rel)`) that today is identity and in Phase 3 maps to a container mount point.

### P14 [medium] Atomic writes via `os.Rename` have no retry, and on Windows that is the single most common transient failure in an artifacts directory.

**Why it breaks:** The claim 'Go uses MoveFileEx with REPLACE_EXISTING, atomic on NTFS' is correct as far as it goes, but `MoveFileEx` with `MOVEFILE_REPLACE_EXISTING` fails with ERROR_ACCESS_DENIED or ERROR_SHARING_VIOLATION when the target file is open without FILE_SHARE_DELETE. On this host that means Defender scanning the just-written `.tmp`, an editor with `run.json` open, or Docker Desktop touching a bind-mounted log. The design already acknowledges exactly this class of problem for *deletion* (the rename-to-.trash fallback in `Retain`) but not for writes, where a failure loses the artifact rather than leaking disk. Every `WriteJSON` (run.json, verdict.json, MANIFEST.json) is exposed.

**Fix:** Wrap the rename in a bounded retry with backoff (5 attempts, 10ms..200ms) treating ERROR_ACCESS_DENIED/ERROR_SHARING_VIOLATION as retryable; on final failure keep the `.tmp` and record the fact in the manifest rather than dropping the write. Add the same retry to `os.Remove` in the trash sweep.

### P15 [medium] `.gitattributes` uses `*.thesis -text`, which prevents CRLF conversion on checkout but does NOT normalize CRLF on commit from a Windows working tree: the exact direction that matters here.

**Why it breaks:** The design correctly identifies CRLF as 'the most likely thing to actually break this project' and then picks the attribute that only closes half the door. `-text` unsets the text attribute, so git performs no conversion in either direction. Development is on Windows 11 with PowerShell. If any tool, editor, or `Set-Content` writes a `.thesis` with CRLF into the working tree (PowerShell 5.1's `Out-File`/`Add-Content` default to CRLF) `-text` means git commits those CRLFs verbatim. The corrupt file then breaks the strict parser and every `world_hash` on Linux CI and on the original author's own machine. `text eol=lf` would have normalized to LF in the index on commit and checked out LF, closing both directions.

**Fix:** Use `*.thesis text eol=lf` (and likewise `*.jsonl`, `*.json`). Keep `* text=auto eol=lf` as the default. Add the CI check the design already proposes (assert `.gitattributes` content) but assert `text eol=lf`, and add a pre-commit or test-time scan that rejects any `\r` byte in `.prothesis/regressions/*.thesis`.

### P16 [medium] `max_concurrent_faults` is declared and never enforced anywhere, and the design's stated reason for the withdraw-before-inject ordering rule is therefore unfounded.

**Why it breaks:** `Sequencer` declares `sem chan struct{} // max_concurrent_faults` and no code in the design ever reads or writes it. `Compile`'s doc says 'Withdrawals sort before injects at the same instant so `max_concurrent_faults` is never transiently exceeded at a window boundary', but nothing checks the budget at any instant, transient or otherwise, so the ordering rule protects an invariant that does not exist. Under addendum E.2, `max_concurrent_faults` and `max_faults_per_world` are lock-protected anti-gaming floors: narrowing them is a lock change requiring a human-reviewed commit. A world that silently exceeds them (from Phase 4 mutation) or silently under-runs them produces a verdict whose fault coverage does not match what the lock says was executed, which is an I6 hole in the opposite direction from the one the design guards.

**Fix:** Decide and document the enforcement point. The right one is world *validation* (a pure `ValidateWorld(w, budget) error` living with the schema), so search mutation and shrink both get rejected before execution and `thesis replay` of a corpus world can detect that the budget was tightened since the world was recorded. Delete `sem` or wire it. Record the executed concurrency high-water mark in `run.json` so the verdict can be checked against the lock.

### P17 [medium] `Retain`'s regression-pinning rule is unimplementable against the schema the same document defines.

**Why it breaks:** `Retain` states 'A run referenced by any `.prothesis/regressions/*.thesis` is NEVER pruned.' But `World` contains DriverProfile, FaultSchedule, Notes, Origin, PhaseTimings, Schema, Seed, TopologyVariant, WorldHash, and `WorldOrigin` contains Commit, ConfigHash, CreatedBy, ToolVersion. There is no run_id anywhere. There is no way to resolve a regression world to the run that produced it, so retention will prune the run directory containing the history.jsonl, logs and timeline that are the only evidence for the committed regression. This is exactly the artifact a developer reaches for when a regression starts failing.

**Fix:** Add `run_id` (and optionally `world_ordinal`) to `WorldOrigin`. It is provenance, so it stays out of `HashableKeys` and does not disturb dedupe, which is precisely why the projection design accommodates it cleanly. Then `Retain` can build the pin set by scanning regressions.

### P18 [medium] The recorder mutating `min_window_ms` based on host clock calibration makes execution a function of the host, violating I2.

**Why it breaks:** §1.5: 'Above 5ms, the recorder raises `min_window_ms` and warns.' `min_window_ms` is not in the `prothesis.yaml` schema, and if it alters how a world's fault windows execute then the same `.thesis` produces different behaviour on a fast host and a slow one: the world tuple no longer determines the run. Combined with the fidelity table (a window shorter than lateness is skipped entirely), a regression world that reproduces 3/3 on CI can silently execute zero faults on a laptop and report PASS. Under addendum PART 5's Tier B honesty rule the verdict must 'never claim determinism it does not have': a PASS from a world whose faults were all skipped is worse than a non-claim.

**Fix:** Never let calibration change execution. Measure `sleep_granularity_ns`, record it in `clock.json`, and if it exceeds a threshold that would make the world's narrowest window unexecutable, refuse to run that world and report INCONCLUSIVE with the measured granularity, rather than quietly widening windows or skipping faults.

### P19 [low] The stated `run_id` length is wrong (17, not 21), `Seek` truncates above 2^38 bytes, and the MAX_PATH budget does not close.

**Why it breaks:** Three small, concrete arithmetic errors that will be coded as constants. (1) `r_2026_09_03_a41f` is 17 characters; the doc comment says '(21 chars)'. A length assertion of 21 rejects every valid run_id. (2) `func (s *Stream) Seek(n uint64) { s.block = uint32(n / 64) }` silently truncates for n >= 2^38 (= 274877906944, exactly the 2^32-block x 64-byte capacity), so an out-of-range Seek wraps to a valid-looking but wrong position instead of erroring: a determinism bug that produces plausible values. (3) The MAX_PATH story does not close: `.prothesis/runs/<17>/worlds/000000/logs/` is 53 chars, plus a `SafeName`-legal 64-char node id plus `.stderr.log` is 128 chars of relative path, against a stated 150-char budget for the artifacts dir root; total 278, over the 260 limit, and the design already notes that external tools invoked on those paths will not get `\\?\` handling.

**Fix:** Fix the comment to 17. Make `Seek` return an error (or panic) above the 2^38 cap and specify the nonce/counter byte order while you are there: it is currently unspecified, which defeats the cross-language reproduction that is the stated reason for hand-rolling ChaCha20. Recompute the path budget from the longest real path (cap node ids at ~24 chars in `SafeName`, or budget the root at 110).

### P20 [low] `NewRealClock` starts an unstoppable drift goroutine that must emit into a Bundle that does not exist yet.

**Why it breaks:** `NewRealClock` does `go c.watchDrift()`, and `watchDrift` calls `c.emit("clock.anomaly", ...)` which writes to `timeline.jsonl`. But `OpenBundle(artifactsDir, clock)` takes the clock as a parameter, so the clock is constructed strictly before the bundle exists: the emit target is nil for the first interval and there is no wiring described to attach it later. `realClock` also has no `Close`, despite `SleepUntilR`'s doc saying it returns when 'the clock closes'; in `thesis watch` (a long-lived daemon per addendum PART 7) that is a goroutine and ticker leaked per run.

**Fix:** Buffer anomalies in the clock and have `Bundle` drain them on attach, or invert construction so the clock takes an emit sink that starts as a no-op and is set once. Add `Close() error` to the `Clock` interface, stop the ticker, and make `SleepUntilR` honour it as documented.

## Missing

- Driver-time to virtual-time mapping. Phase 0 must fix the anchor that converts the external driver's absolute `t_ns` (spec §4.4: `"t_ns":1725300000000000`) into the `v_ms` frame of `oracle_input.phases`. The design records one `clock.origin` wall_ns, then states 'Docker Desktop's Linux VM has its own clock; container log timestamps are in that clock, not ours' and stops. Without a measured driver-clock offset, I5 phase-aware assertion is not evaluable in Phase 3, and the `NowWall()` doc comment claiming it 'guarantees non-decreasing timestamps in history.jsonl' is false: the recorder does not write history.jsonl.
- `pkg/schema` types for `prothesis.yaml`. This is an explicit Phase 0 deliverable ('Define Go types for `prothesis.yaml`, `.thesis` world files, history logs, and verdicts'). The design mentions `schema.ArtifactsConfig` once and otherwise never addresses config: no types, no story for how YAML is parsed given 'minimize third-party dependencies' and no stdlib YAML package, and no definition of the 'CJSON projection of prothesis.yaml' that `config_hash` is computed over, which Phase 3's `.prothesis/lock` depends on.
- `pkg/schema` types for the history log, also a named Phase 0 deliverable. The design only says history.jsonl is CJSON-exempt and read with `UseNumber()`. Addendum §M's normative rule ('`ok` = definitely happened, `fail` = definitely did NOT happen, `info` = indeterminate. Drivers that cannot distinguish MUST emit `info`') has no representation and no validator.
- An `Undo` idempotency contract. The scheduled `OpWithdraw` event and the deferred `drain()` both target the same fault, so `Undo` will be invoked twice per successful inject in any correct version of this design. `Actuator`'s doc only states that `Do` 'MUST be safe to retry'.
- Any enforcement point for `perturber.budget.max_concurrent_faults` / `max_faults_per_world`. `Sequencer.sem` carries the comment `// max_concurrent_faults` and is never used in any shown code path, and no other component is named as the enforcer. Under addendum §E.2 these are lock-protected floors.
- A run back-reference in the world schema. `Retain`'s rule 'A run referenced by any `.prothesis/regressions/*.thesis` is NEVER pruned' cannot be implemented: neither `World` nor `WorldOrigin` carries a run_id.
- `thesis up` → `thesis down` state handoff. Phase 0 DoD (a) requires `up` to boot and a separate later `down` to destroy. Nothing persists the compose project name, network, or container ids across the two invocations. The recorder owns `.prothesis/` layout and offers only `runs/<run_id>/RUNNING`, whose stated semantics ('absent => clean teardown') are about a run, not a live topology, and which `Bundle.Close()` deletes.
- Byte-order specification for `Stream.Index(i uint64)` into the 12-byte ChaCha nonce, and for the `Seek` block/offset mapping. The stated justification for hand-rolling ChaCha20 is cross-language reproducibility ('A Python or Rust oracle can reproduce HMAC-SHA256 + ChaCha20 exactly'; addendum PART 10 portability). An unspecified nonce encoding defeats it, and no golden vector in test 12 would catch a Go-internal-consistent-but-nonstandard choice.
- A path-translation seam for `oracle_input.history_path` / `final_state_path` / `telemetry_path` / `world_path`. Phase 3's named linearizability checkers (Elle/Knossos, JVM/Clojure) will run in containers on this Windows host, where a `C:\...` absolute path is meaningless. The design commits Phase 0 to host-absolute paths.
- Any acknowledgement that on this host the artifacts root is `C:\AI Projects\Pro-synthesis` (a path containing a space) while `driver.cmd` is a string template (`--history {history_path}`) with no stated argv/quoting model. `SafeName` covers node ids only.
- The test matrix the design leans on cannot exist in Phase 0. §3.8 says the ladder 'runs in CI on a matrix of Go 1.22/1.23/1.24 × {windows/amd64, linux/amd64, linux/arm64, darwin/arm64}' and that 'the cross-platform matrix is what makes it convincing rather than merely green'. Go is not installed, the directory is not a git repo, there is no CI, and only Windows is available. Phase 0's byte-identity evidence therefore rests on the single-platform subset, which is fine, but the design should say so and identify which specific tests (schema Lint, map-order chaos, cross-build determinism with `-gcflags=all=-N -l` vs optimized) actually carry DoD (b) on one machine.
- What the `process` backend does on Windows. Not a Phase 0 deliverable, but `Actuator` is the only seam that absorbs it, and the design never notes that `proc.pause` (SIGSTOP/SIGCONT) and `net.partition` (iptables) are impossible for a Windows `process` backend: meaning `Actuator.Do` must be permitted to return a 'capability unavailable' result distinct from failure, or every `process`-backend run on this host becomes exit 2.
