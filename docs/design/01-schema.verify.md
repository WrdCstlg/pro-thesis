# 01-schema.verify

## Verdict

**NEEDS-REVISION**

## Spec fidelity

The design is unusually disciplined about labelling its own additions, but it does drift, and in three places the drift is not labelled.

UNLABELLED DRIFT (the ones that matter):

1. Severity re-grading. Design: `case ClassConsistency, ClassSafety: return SeverityCritical`. Directive §4.6, the only normative severity value in either document: `"oracle": "linearizable.kv", "class": "consistency", "severity": "high"`. `ToViolation` assigns from the table unconditionally, so the Phase 3 DoD violation is emitted at a grade the frozen example contradicts. The four-level ladder itself is flagged as inferred; the fact that the table disagrees with the worked example is not.

2. `t_ns` origin. Design: "TNS is nanoseconds on the recorder virtual clock, with t=0 at DRIVE start. BOOT and SEED records are therefore NEGATIVE." Directive §4.4: `{"t_ns":1725300000000000,...}`; I evaluated the sample values; read as unix microseconds they are 2024-09-02T18:00:00Z, i.e. epoch-derived wall clock. Under the design's rule the same literal means 19.97 days after DRIVE start. The design labels this an open question but has already frozen the opposite answer into the type, into `EventTOrigin`, and into a fixture it calls a verbatim copy of the spec.

3. Exit 3 semantics. Directive §4.7: "`3`: BUDGET_EXHAUSTED; Budget expired **without coverage progress**". Design: `ExitCode.Verdict()` is documented as "the total bijection between exit code and verdict string" with no coverage term anywhere.

LABELLED-BUT-LOAD-BEARING ADDITIONS (accept only with a DECISIONS.md line each):
`WorldSchema = "prothesis.world/v1"` (the directive names no schema id for `.thesis`); `CoverageDelta.States` (directive sample has only `templates` + `note`); `TimelineEvent.Node` always present (directive omits it on 3 of 4 sample rows); `Provenance` as a whole; `PlaceholderProfileJSON` / `EnvDriverProfile`; `MaxSeed`; `TargetAll` (`*`; the directive's target list is node/wildcard/role/edge/quorum, with no bare `*`); `LockAbsent`; `EventTOrigin`.

INVENTED CONSTRAINTS PRESENTED AS VALIDATION, NOT AS ADDITIONS (these are the quiet ones):
`sum(mix) == 1.0 ± 1e-6`; `driver.cmd` must contain `{history_path}`; history op records must carry `process` AND `op_id`; `seed >= 1`; `"role"` is a reserved service name; `k8s`/`sim` backends parse but fail `Validate` with exit 5. None of these appear in either document. The last one is probably right (CRUCIBLE PART 9: "Does not require Kubernetes in v1") but it is still an invented CONFIG_ERROR on a value the directive's own comment lists as legal (`backend: compose # compose | process | k8s | sim`).

INFERRED-AS-NORMATIVE: the six `VerdictResult` values are presented as "the `verdict` field of prothesis.verdict/v1. Six values". The directive only ever exhibits `"FAIL"`; the other five are back-derived from the exit-code NAMES in §4.7, which is a reasonable inference but is an inference, and `CONFIG_ERROR` as a *verdict document value* is questionable: a config error means no run happened.

NO DRIFT FOUND (worth stating, since these are the highest-risk surfaces): the eight phase names, the six exit-code numbers and names, the oracle exit space 0/1/2, the eight oracle classes, the three oracle statuses, the six built-in oracle names, the 17-kind fault matrix, every field name in `prothesis.yaml`, `prothesis.verdict/v1`, `prothesis.oracle_input/v1` and `prothesis.oracle_output/v1`, and the fault canonical printer; I checked the printer against the directive's own `surviving_faults` strings and both round-trip exactly: `proc.pause(role:leader)@8200..15100` and `net.partition(minority(kv))@8400..14900`.

## Confirmed problems (14)

### P1 [high] `RetainPolicy.UnmarshalYAML` (and `Duration.UnmarshalYAML`'s bare-number branch) rely on yaml.v3 FAILING to decode an integer scalar into a Go string. It does not fail. The directive's own golden config line `retain_passing: 3` will therefore be rejected as a CONFIG_ERROR.

**Why it breaks:** yaml.v3's `decoder.scalar` has, inside `switch out.Kind()`, a `case reflect.String: out.SetString(n.Value); return true` arm that is reached for ANY scalar node regardless of resolved tag. So for `retain_passing: 3`, `unmarshal(&s)` returns nil with `s == "3"`. The design's code is `if err := unmarshal(&s); err == nil { return r.set(s) }` and `r.set` only accepts "all": it returns `retention must be a non-negative integer or "all", got "3"`. The `var n int` branch below is unreachable dead code. `TestGoldenConfigDecodes`, which asserts `retain_passing == RetainN(3)`, cannot pass. Identical root cause kills `Duration.UnmarshalYAML`'s friendly bare-number diagnostic: `budget: 90` decodes to s="90" and falls into `parseDurationText`, so the advertised message `write "90s" if you meant seconds` is never emitted. Same trap will fire on `worlds: -1` if `*int` is ever given a string-first custom unmarshaller, and on any future string|number union.

**Fix:** Do not use the obsolete func-based unmarshaller for polymorphic scalars. Either (a) implement `UnmarshalYAML(n *yaml.Node) error` and branch on `n.Tag` (`!!int` vs `!!str`), which requires `pkg/schema` to import yaml.v3 and kills rule 2 of the design; or (b) keep the obsolete interface but decode into `any` first and type-switch on the dynamic Go type (`int`, `string`) rather than probing with `unmarshal(&s)`. Option (b) preserves the zero-dependency goal. Add a test that decodes `retain_passing: 3` AND `retain_failing: all` from the verbatim golden YAML before writing any other schema code: it is the cheapest possible detector for this whole class of bug.

### P2 [high] The verdict 'total contract' (no `omitempty`, absent scalars are `""`) collides head-on with the strict `UnmarshalJSON` methods on `Phase`, `OracleClass`, `Severity` and `VerdictResult`. A verdict PRO-THESIS emits cannot always be read back by PRO-THESIS.

**Why it breaks:** `Violation.Phase Phase `json:"phase"`` has no omitempty, and `Phase.UnmarshalJSON` calls `ParsePhase`, which rejects `""` (`ParsePhase("")` -> `Phase("")` -> `Valid()` false -> error). A resource or crash violation not scoped to a lifecycle phase emits `"phase":""`, which then fails to decode. The same holds for `Violation.Class`: `DecodeOracleOutput` is explicitly documented as LENIENT about missing optional fields, so a third-party oracle that omits `class` yields `Class == ""`, `ToViolation` copies it verbatim into the Violation, and the emitted `"class":""` is unreadable by `OracleClass.UnmarshalJSON`. This bites `thesis report <run_id>` (Phase 6), any regression-corpus reader, and the design's own `TestGoldenVerdictDecodesAndReEmits`.

**Fix:** Pick one and enforce it in `Normalize()`: either (a) `Normalize()` fills every closed-enum field with a defined sentinel before emit (`Phase` gains an explicit `"UNSCOPED"` member; `DecodeOracleOutput` defaults a missing class to a defined value rather than ""), or (b) the strict `UnmarshalJSON` methods accept the empty string as 'absent' and let `Validate()` decide whether that is legal in context. (a) is better because it keeps the contract total for agents. Add a property test: for every Violation the emitter can produce, `Decode(Emit(v))` succeeds.

### P3 [high] The design's `t_ns` semantics ('nanoseconds on the recorder virtual clock, t=0 at DRIVE start, BOOT and SEED records are NEGATIVE') contradict the directive's own §4.4 sample, whose t_ns values are absolute and wall-clock-derived. The design presents this as an open question but has already frozen the answer into the type and into `history.golden.jsonl`.

**Why it breaks:** The sample values are `1725300000000000`, `1725300000410000`, `1725300001010000`… I evaluated these: as unix microseconds they are 2024-09-02T18:00:00Z, a plausible authoring timestamp; as unix nanoseconds they are 1970-01-20. Either way they are epoch-derived, not a virtual clock starting at 0. Under the design's rule, `1725300000000000` means '1,725,300 seconds after DRIVE start': 19.97 days into a 90-second smoke run. So `pkg/schema/testdata/history.golden.jsonl`, copied verbatim per §17, contains records that are semantically absurd under the design's own semantics, and any test that computes a phase for those records via `PhaseTimings.At(ms)` will get nonsense. The design also needs `EventTOrigin` (an ADDITIVE marker) purely to recover what the spec's chosen encoding gave for free. This is not a cosmetic choice: the design correctly identifies that changing the origin later invalidates the whole accumulated corpus, and it is choosing the origin that disagrees with the spec.

**Fix:** Either adopt the spec's evident semantics (t_ns = absolute nanoseconds since the unix epoch; oracles derive DRIVE-relative ms by subtracting the DRIVE window origin carried in `oracle_input.phases`, which is already normative and already DRIVE-relative); this needs no ADDITIVE `t_origin` marker and keeps the golden file honest; or keep the virtual-clock origin but STOP calling `history.golden.jsonl` a verbatim spec fixture, record the reinterpretation in OPEN_QUESTIONS.md as a deviation, and regenerate the fixture. Do not ship both.

### P4 [high] Dynamic targets (`role:leader`, `minority(kv)`, `majority(kv)`, `kv:*`) are stored only unresolved in `WorldCore.FaultSchedule`, and the schema has nowhere to record WHICH concrete node a dynamic target resolved to at injection time. This breaks I2 self-containment and makes Phase 5's `reproduced: "k/n"` far worse than it needs to be.

**Why it breaks:** Under Tier B (the v1 default, per CRUCIBLE PART 5) the system under test keeps its own nondeterminism, so leader election is not reproducible. `proc.pause(role:leader)@8200..15100` (the directive's own example, and its Phase 2 DoD schedule) resolves to n2 on the discovering run and possibly n1 on replay. A world that replays a DIFFERENT physical fault is not, in the words of I2, 'a self-contained .thesis file that reproduces the issue'. This is a Phase 0 foreclosure, not a Phase 5 concern: `world_hash` covers exactly `WorldCore` and the regression corpus is append-only and lock-covered (CRUCIBLE E.4), so adding a resolution field to the world in Phase 5 rehashes every archived world and reads as a lock change.

**Fix:** Decide now, in Phase 0, and write it in DECISIONS.md. Two viable shapes: (1) add a `resolutions map[string]string` (canonical fault string -> concrete node id) to `Provenance`, NOT hashed, so it is advisory replay guidance that never changes world identity, and `thesis replay --pin-targets` can honour it; or (2) declare explicitly that resolution logs live in the run artifact bundle (`.prothesis/runs/<run_id>/`), never in the world, and that `reproduced: k/n` is expected to be lower for worlds containing dynamic targets. Either is defensible; silence is not, because the cost of choosing later is a corpus-wide rehash.

### P5 [medium] `TestGoldenVerdictDecodesAndReEmits`: 'decode the spec verdict, re-emit, compare canonicalized forms'; cannot pass, because the design's own ADDITIVE always-present fields make the re-emitted document a strict superset of the spec sample.

**Why it breaks:** Re-emission adds `"states":0` to `coverage_delta_vs_baseline` (the directive's sample has only `templates` and `note`) and adds `"node":""` to three of the four `causal_timeline` rows (the directive omits `node` on the `fault`, `fault` and `op` rows and supplies it only on the `log` row). Canonicalized comparison is byte equality after key sorting; a superset is not byte-equal. The design lists this test as protection for the frozen contract, so it will be the first test written and the first to fail, and the likely reflex will be to weaken the test rather than to question the additive fields.

**Fix:** Restate the test as containment, not equality: assert every key/value in the spec sample is present with the same value in the re-emitted document, and separately assert the set of extra keys equals a frozen, explicitly-enumerated ADDITIVE allowlist. That turns 'we added a field' into a deliberate one-line edit with a reviewer, which is what the additive-fields policy actually wants.

### P6 [medium] `DefaultSeverity(ClassConsistency) == SeverityCritical` contradicts the only normative severity value in the directive, which pairs `"class": "consistency"` with `"severity": "high"`.

**Why it breaks:** Directive §4.6 verdict sample: `"oracle": "linearizable.kv", "class": "consistency", "severity": "high"`. The design's table is `case ClassConsistency, ClassSafety: return SeverityCritical`. `ToViolation` assigns severity unconditionally from this table, so the Phase 3 DoD ('the fixture lease bug is flagged as a linearizable.kv consistency violation') will emit `"severity":"critical"` where the spec's worked example says `"high"`. Any CI policy or agent branching on severity thresholds derived from the spec sample sees a different grade than the spec advertises.

**Fix:** Make `high` the default for consistency (and for safety), reserving `critical` for nothing in v1, or drop the four-level ladder entirely and emit only `"high"`; the single value the frozen contract actually exhibits. If a ladder is genuinely wanted, put it in DECISIONS.md with the explicit note that it re-grades the directive's worked example, and get sign-off.

### P7 [medium] `Config.Validate()` is monolithic and gates every command on the whole file, including fields no Phase 0 command touches. This directly threatens Phase 0 DoD (a).

**Why it breaks:** `thesis up` and `thesis down` need only `version`, `name`, `harness.backend`, `harness.file`, `harness.nodes` and `harness.health`. The design's `Validate()` additionally requires `driver.cmd` non-empty AND containing `{history_path}`, at least one driver profile with `clients>0`/`ops>0`/`mix` summing to 1.0±1e-6, `perturber.budget.max_concurrent_faults >= 1`, `max_faults_per_world >= 1`, every `oracles.builtin` name valid, and at least one top-level profile with `budget > 0` and a resolving `driver_profile`. Any non-nil result maps to exit 5. So `thesis up` on a config that has a perfectly good harness section but a placeholder driver fails with CONFIG_ERROR, and Phase 0's definition of done depends on `thesis init` scaffolding a config that satisfies validation rules for three subsystems that do not exist yet.

**Fix:** Split validation by required section: `Config.ValidateHarness()`, `ValidateDriver()`, `ValidatePerturber()`, `ValidateOracles()`, `ValidateProfiles()`, with `Validate()` as the union used by `run`/`gate`. `up`/`down`/`init` call only `ValidateHarness()`. This costs nothing, keeps the fail-closed posture where it matters, and makes Phase 0 DoD (a) reachable without a fully-populated config.

### P8 [medium] `UnmarshalWorld` uses `dec.DisallowUnknownFields()` AND `FaultSpec.UnmarshalJSON` calls the registry-strict `ParseFault`. Together these make the append-only regression corpus (CRUCIBLE E.4) unreadable the moment any later phase adds a world field or a fault kind.

**Why it breaks:** Shrunk worlds are written to `.prothesis/regressions/` and committed to the repo, and `thesis regress` runs the whole corpus on every gate invocation forever. If Phase 4 adds a coverage-provenance field or Phase 2 renames a fault parameter after prototyping against real tc/netem (a risk the design itself names) every committed `.thesis` becomes a hard decode error, and `thesis regress` returns exit 5 or 2 for worlds that are otherwise perfectly valid. The design provides `ParseFaultLoose` explicitly 'for rendering faults produced by a newer tool version' but never wires it into any ingestion path, so its stated purpose is unreachable.

**Fix:** Keep `DisallowUnknownFields` for `prothesis.yaml` (that is the anti-gaming surface) but relax it for `.thesis`: preserve unknown top-level keys in a `map[string]json.RawMessage` that is excluded from `WorldCore` and therefore from `world_hash`, so old readers pass them through. For fault kinds, add a `thesis regress` path that uses `ParseFaultLoose` and reports an unknown kind as INCONCLUSIVE (exit 2, 'this world needs a newer thesis') rather than CONFIG_ERROR. Note in DECISIONS.md that unknown-field tolerance in `.thesis` is safe precisely because the hash covers only the five normative tuple members.

### P9 [medium] `Config.LockPayload()` under-covers what CRUCIBLE PART 6.3 mechanism 1 requires, and the design contradicts itself about whether `perturber.constraints` is inside the lock.

**Why it breaks:** CRUCIBLE E.1: the manifest holds 'a hash manifest of every oracle definition, the allowed fault space, and profile budgets.' `LockPayload` is documented as 'the fault space, the perturber budget, and every profile budget': oracle definitions are entirely absent, including `oracles.builtin` (the list of built-ins in force) and `oracles.dir`. Deleting `no_stuck_op` from `oracles.builtin` is exactly the gate-weakening I6/E.1 exist to catch, and this payload does not catch it. Separately, the `Perturber.Constraints` comment claims 'Phase 0 stores them verbatim and hashes them into the lock' while `LockPayload`'s own doc comment does not include them: one of the two is wrong, and since the design's stated purpose for defining `LockPayload` in Phase 0 is 'so Phase 3 cannot quietly change what is covered', an under-specified payload defeats its own rationale.

**Fix:** Extend `LockPayload` in Phase 0 to include, at minimum: `oracles.builtin` (sorted), `oracles.dir`, `perturber.constraints` (verbatim, sorted), the effective fault space, the perturber budget, and every profile's budget and worlds count. Resolve the constraints contradiction in one direction and state it once. Leave the per-file oracle-script digests to Phase 3 but reserve the key now (`"oracle_digests": {}`), so adding them is not itself a manifest change.

### P10 [medium] `Validate` requires `seed in [1, MaxSeed]`, silently making seed 0 a CONFIG_ERROR.

**Why it breaks:** `thesis run --seed N` and `thesis replay` are normative CLI surface (CRUCIBLE PART 7). Seed 0 is the single most likely value a user or a test writer types, and it is also the zero value of `uint64`, so a `World{}` literal in any test fails `Validate()` for a reason that has nothing to do with what the test is checking. Nothing in either spec reserves 0 or requires a nonzero seed; the constraint exists only so 'unset' is distinguishable from 'zero', which is a problem the design solves with pointers everywhere else in the tree.

**Fix:** Allow seed 0. If 'unset' must be distinguishable at the CLI layer, use `*uint64` on the flag struct, not a forbidden value in the frozen world tuple. Keep the `MaxSeed = 2^53-1` upper bound: that one is genuinely earned by the jq/JavaScript-consumer argument.

### P11 [medium] Several invented CONFIG_ERROR conditions have no basis in either spec and will reject legitimate configurations: `sum(mix) == 1.0 ± 1e-6`, `driver.cmd` must contain `{history_path}`, and history operation records must carry both `process` and `op_id`.

**Why it breaks:** (1) Nothing in §4.2 says `mix` is a probability distribution; relative weights (`{read: 5, write: 5}`) are the more common load-generator convention and would exit 5. (2) A driver that takes the history path from the `PROTHESIS_*` environment instead of the command line, which the design itself introduces via `EnvDriverProfile`, is rejected. (3) Most damaging: `HistoryEntry.Validate()` returns a hard error for an op record missing `op_id`, and `HistoryReader.Next()` calls `Validate()` per line, so one malformed line from a user-authored `driver.cmd` aborts the whole history read mid-stream. The directive never marks `op_id` mandatory; Jepsen-format histories (the stated compatibility target in §4.4) use `:process` and `:index`. CRUCIBLE PART 10 requires working on unmodified systems, so a strictness that kills a run rather than degrading is a positioning violation, not just a nit.

**Fix:** Drop the mix-sum rule (or demote it to a warning and normalize weights). Drop the `{history_path}` substring requirement; validate instead that at least one of `{history_path}` in cmd or the env-var mechanism is in play. For history: keep the checks but make `HistoryReader.Next()` return the entry plus a non-fatal per-line diagnostic, and let the caller decide the policy (a run aborts only on a configurable threshold of bad lines). None of these three rules protect against gate-weakening, so relaxing them is not the forbidden kind of relaxation.

### P12 [medium] The `Capability` model is too coarse for the actual Windows/Docker Desktop host: `CapProcCtl` conflates spawn/kill/restart, so `proc.kill(n1, signal=SIGTERM)` validates and schedules on the Windows `process` backend and then fails only at injection time.

**Why it breaks:** On Windows, Go's `os.Process.Signal` only meaningfully supports `os.Kill` (TerminateProcess); `SIGTERM`, `SIGHUP` etc. are not deliverable to another process. The design's `ParamSignalType` validator accepts anything beginning `SIG` or any integer, and `proc.kill` requires only `CapProcCtl`, which the Windows process backend does provide (it can spawn and terminate). So the plan-time capability check (the whole point of the model, and the thing that lets `thesis doctor` say 'unavailable' before a run starts) passes, and the failure surfaces mid-DRIVE as an INCONCLUSIVE. Relatedly, `CapNetFilter`/`CapNetShape` are declared as properties of the BACKEND, but for `compose` they are properties of the user's compose file and image: iptables inside a container needs `cap_add: [NET_ADMIN]`, which Docker does not grant by default, and libfaketime for `clock.*` needs LD_PRELOAD baked into the image. A per-backend static answer will be wrong for any compose file but our own fixture.

**Fix:** Split `CapProcCtl` into `CapProcSpawn`, `CapProcTerminate` and `CapProcSignal` (arbitrary POSIX signal delivery), and make `proc.kill` require `CapProcSignal` only when `signal != SIGKILL`. Keep the capability *provider* side dynamic and per-node rather than per-backend, so the compose backend can probe `cap_add`/`NET_ADMIN` and the presence of `tc`/`sch_netem` inside each container during BOOT and report honestly. The schema side of this is just the enum granularity: get it right in Phase 0, because `Requires` is baked into the frozen registry.

### P13 [medium] `ExitCode.Verdict()` presents exit 3 as an unconditional bijection with budget expiry, dropping the directive's qualifier.

**Why it breaks:** Directive §4.7: '`3`: BUDGET_EXHAUSTED; Budget expired **without coverage progress**; soft warning.' The design's `Verdict()`/`ExitCode()` pair is a total bijection with no coverage input, so the control plane will naturally map any budget expiry to 3. A soak run that expires having found no violations but having added 200 new log templates should be PASS (0), and under this table it becomes a 'do not merge blind' soft warning that an agent loop will treat as a degraded result forever.

**Fix:** Keep the bijection as the *encoding* but add an explicit, documented decision function on the control side: `func Decide(violations []Violation, budgetExpired bool, coverageDelta int) VerdictResult`, where budget expiry yields BUDGET_EXHAUSTED only when `coverageDelta <= 0`. Put the coverage condition in the doc comment on `VerdictBudgetExhausted` in Phase 0 so Phase 1 cannot lose it.

### P14 [low] `ComputeHash`'s apparent defensive copy (`c := w.WorldCore`) does not protect the caller, because `FaultSchedule` and `PhaseTimings` are slices and `Normalize()` is described as an in-place stable sort.

**Why it breaks:** Copying a struct copies slice headers, not backing arrays. `c.normalize()` calls `c.FaultSchedule.Normalize()`, which sorts the array shared with `w.WorldCore.FaultSchedule`. So `w.ComputeHash()` (presented as a pure read) reorders the caller's fault schedule. For Phase 5 this matters: `ddmin` iterates over candidate subsets and will want to hash a candidate without disturbing the parent's ordering, and a search loop that hashes a child mid-mutation silently mutates the corpus entry it was derived from. The bug is invisible because the sort is idempotent, so the first symptom will be a Phase 4/5 heisenbug rather than a failing Phase 0 test.

**Fix:** Make `FaultSchedule.Normalize()` return a fresh slice (`out := append(FaultSchedule(nil), s...)`, sort `out`, return it) and document it as non-mutating; the doc comment already implies this by returning a value. Add a test asserting that `ComputeHash` on a deliberately out-of-order schedule leaves the receiver's slice order untouched.

## Missing

- Seed-stream derivation contract. `WorldCore.Seed` is the root of I2 reproducibility and Phase 0's sibling deliverable is explicitly 'deterministic PRNG seed streams' (§6 Phase 0, internal/recorder), but the schema defines no normative derivation from the world seed to per-subsystem streams (perturber timing, driver op order, client scheduling). Whatever recorder picks becomes an unwritten part of the world contract, and changing it later invalidates every archived world exactly as surely as changing world_hash does. This belongs in pkg/schema (or at minimum in DECISIONS.md) in Phase 0: a documented rule like `stream_i = sha256(seed || stream_name)` costs nothing now and is unrecoverable later.
- No schema for `final_state.json` or `telemetry.json`, despite both paths being normative members of `prothesis.oracle_input/v1`. Phase 1's `resource_return_to_baseline` (RSS/FDs/goroutines vs baseline) and `no_unbounded_queue` (queue depth across QUIESCE) cannot be written without telemetry's shape, and every external oracle needs it too. The design delivers 'all seven contracts complete' but these two are wire contracts the directive names and the design leaves as bare `string` paths.
- No representation for resolved dynamic fault targets (see confirmed_problems). Nothing in `WorldCore` or `Provenance` records which node `role:leader` or `minority(kv)` actually selected.
- No `.prothesis/lock` structure at all, and `LockPayload()` omits oracle definitions, which CRUCIBLE E.1 names first in the manifest. The design justifies deferring the lock FILE to Phase 3, which is right, but the PAYLOAD is defined in Phase 0 precisely so it cannot drift, and as defined it already fails to cover the primary anti-gaming surface.
- No coverage record types. `Coverage` carries four counters but there is no log-template record and no state-abstraction tuple type `(role, term/epoch, bucketed_queue_depth, connection_count, bucketed_lag)`. CRUCIBLE PART 4.2 ranks log-template coverage as the thing to 'implement this FIRST' and names it 'the highest signal-to-integration-cost ratio in the whole system'. Phase 4 will need these serialized into the corpus; deferring the type is fine, but nothing reserves the shape and the corpus is long-lived.
- `Provenance.DeterminismTier` is a bare `string` with the comment `"B" in v1`. CRUCIBLE PART 5 makes the tiers normative and `thesis doctor` a normative command that scores readiness. Either make it a two-value enum now or drop it from the world.
- `topology_variant` is an undefined bare string in the normative world tuple. Nothing says what it names or how it maps to `harness.file` / a compose profile. The design defaults it to `"default"` and moves on, but this is one of the five hashed members of the world identity: two worlds with different compose topologies and the same variant string hash identically and are treated as the same world by the corpus and by shrink.
- `thesis init`'s scaffolded config template. The design owns config validation and lists `init` as a Phase 0 deliverable's consumer, but never specifies what init writes, and Phase 0 DoD (a) is entirely downstream of it. Concretely, if init copies §4.2 verbatim it will scaffold `steady_state: { probe: "thesis-helpers/steady.sh" }`, which cannot run on this host: Git Bash is broken (I confirmed it during this review; `dofork: child -1 ... Resource temporarily unavailable`). SEED is Phase 1 so DoD (a) survives, but the template bakes in an unrunnable probe on the target machine on day one. The schema should at least document that an exec probe is exec'd directly, not via a shell, so a `.sh` is never the scaffolded default on Windows.
- No handling for `driver.profiles` name collision with the top-level `profiles` map. `Profile.DriverProfile` is validated to resolve in `driver.profiles`, but nothing forbids or defines the case where a top-level profile and a driver profile share a name (both are called `smoke`, `gate` and `soak` in the directive's own sample). This is fine today and will be confusing forever; one sentence in the doc comment fixes it.
